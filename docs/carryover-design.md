# 「正文可持续发展」设计基线（2026-10-14 用户确认）

## 目标

日报正文以**把当天工作讲清楚**为先。目标字数（默认 200）是**下限**，不是上限——
正文超过 200 字时**不要**为了凑数而砍内容；只有确实「讲不完」的部分才暂存到 backlog，
留给后续**没有工作内容的日子**补交。

## 决策一：分类隔离

backlog 条目带 `kind` 字段区分性质：

| kind | 含义 | 可用于补交 |
|---|---|---|
| `completed` | 已完成的工作 | ✅ 是 |
| `plan` | 计划 / 待办 / 未来时内容 | ❌ 否 |

- 「明日计划」字段的内容入队时标 `kind: "plan"`，**永不**被 `_fill_from_backlog` 取用。
  （原因：计划是未来时，拿去充当某天的「今日完成」等于拿计划冒充成果。）
- `backlog.take()` 默认只返回 `kind == "completed"`；需要时可通过参数显式取 plan。
- 旧条目（无 `kind` 字段）按 `completed` 处理，保持向后兼容。

## 决策二：按主题完整性裁剪

「主题」的可落地定义（依据证据里真实存在的字段，不要另造）：

- `codex` 条目 → `project`（如 `E:\project\VR`）
- `git` 条目 → `project` / `source_path`（仓库路径）
- `markdown` 条目 → `path` 的父目录

裁剪规则：

1. 只有当正文**确实超过**目标字数时才考虑裁剪；未超过则原样保留。
2. 按「主题块」切分正文——**同一主题的内容必须整体留在同一篇日报里**，不允许把同一主题
   切一半留一半（那是把当天工作讲残）。
3. 选取策略：优先保留字数更多/更核心的主题块，直到**至少**达到目标字数；
   达到下限后**停止**，把剩余的**完整主题块**入队 backlog。
4. 边界仍不得切断句子（沿用既有 `_split_sentences` / `_cut_at_boundary` 的句边界约束）。
5. 若只有一个主题块且它超过目标字数 → **整块保留**，不入队（宁可当天日报长一点，
   也不能把当天唯一的工作讲残）。

## 与既有实现的关系

- 既有 `_apply_carryover` / `_fill_from_backlog` 的骨架、接线点、`verified` 后才消费、
  `backlog --show/--prune/--clear` 子命令**都保留**。
- 本次要改的是：`plan_extra` 入队时的 `kind` 标注、`take` 的 kind 过滤、
  `_cut_at_boundary` 改为按主题块裁剪。
- 硬约束不变：不得削弱 hash / template_fingerprint / date_encoding / 查重 /
  unknown 不重试 / 已提交草稿不可覆盖；不得改既有函数签名与既有测试断言。
