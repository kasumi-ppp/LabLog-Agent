# 故障排查

先看命令返回的 error/blockers 和 `data/` 中本地证据、回执。生成、预览和 dry-run 不会提交；只有 verified 代表提交后已读回核对。

| 情况 | 处理 |
| --- | --- |
| 找不到 dws/codex | 在本地配置填写已安装的原生 .exe 绝对路径；不要把 .ps1/.cmd 拼成 shell 命令 |
| 未登录/拒绝访问/认证目录被锁 | 区分沙盒权限与真实认证问题；先在正常用户终端运行同 profile 的只读 auth status，禁止删除认证或盲目重新登录 |
| 组织/账号不匹配 | 停止；核对 config.local.yaml 身份，不自动选第一个 profile |
| 模板发生变化 | 重新 doctor、generate、preview；重新核对所有字段及 hash |
| 收件人错误 | 同组织精确查询姓名并读取通讯录，不能默认取第一条匹配 |
| 日期编码未知 | 维持阻止提交；仅依据权威字段说明或用户允许范围内已提交日志的读回样本核实。dry-run 不证明日期格式合法 |
| 工时未填写 | 当前用户偏好为留空，程序不填默认值。模板是否要求工时尚未核实；只有用户愿意提供真实工时时才补录并重新生成，不能用消息跨度或 commit 时间猜测，也不能因此保证空值可提交 |
| 没有足够工作记录 | 增加当天真实记录或人工补充；不修改 blocker 强行提交 |
| Codex 日志缺少结尾换行 | 可能仍在写入，保留警告；稍后重新采集，不修改日志 |
| Codex 输出缺少证据或新指标 | 真实性校验拒绝；补充真实证据，重新生成并审阅 |
| 提交超时/结果不明 | 保留本地状态并 reconcile，只读核对；禁止再次调用提交 |
| 读回失败/不一致 | 保留 reportId 和回执，人工核对远端；不要覆盖、删除既有日志 |
| 本地锁已存在 | 先确认是否有活跃进程；不要自动移除锁。中断后的锁和状态应审阅后人工恢复 |
| 缺少新年度日历 | 从正式通知更新带来源的年度 JSON；不能只按周一到周五运行 |
| 计划任务不运行 | 检查 Windows 登录会话、同一执行账号、绝对路径、任务是否已启用、执行策略和 data/scheduler/ 日志 |

隐私过滤不能穷尽所有机密格式。请在发送前审阅摘要；源目录中秘密较多的项目应排除，原始会话和完整 diff 不会作为报告附件上传。不要将 `data/`、本地配置或实际日报强制加入 Git。
