# 向薛老师申请日志自动化使用授权及接收规则确认

核对日期：2026-10-28。适用项目：LabLog-Agent，组织以本人钉钉当前 iSyslab 组织为准。

## 先说明申请什么

当前没有证据证明必须取得企业管理员权限。此前流程是在提交前被本项目的收件人校验阻断，并非钉钉返回了明确的 permission_denied。

`allowAddReceivers=0` 不能单独证明普通成员禁止提交，也不能仅凭该字段确定完整固定接收人名单。优先请老师或日志管理员确认「学生周报」「学生月报」的实际接收规则，并同意本人账号按这些规则自动提交。

本次只读检查发现，本地周期配置已标为启用，接收人记录为赵浩哲、薛志东、王燕三人。这是本地配置状态，不是老师确认的证明；若目标仍是只交给薛老师，应先由管理员确认是否允许针对本人使用单独模板或修改对应设置。不要为只交给一人而擅自改变实验室共用模板。

## 可以直接发送的申请文字

薛老师您好，我在做一个用于本人工作汇报的本地自动化工具，希望申请在实验室允许的范围内使用。

工具每周日22:00开始汇总当周日报生成周报，每月最后一天22:00开始汇总当月日报和周报生成月报，并以本人账号提交。考勤、请假、培训、公共服务等没有明确记录的内容会注明待补充，不会自动推断。

想请您或日志管理员帮忙确认：

1. 是否同意我以本人账号自动提交学生周报和学生月报？
2. 这两种报告应只发给您，还是需要同时发给其他老师？请确认完整接收人名单。
3. 如果现有模板已固定接收人且符合实验室要求，是否可直接沿用？如果我的账号不在模板使用范围，烦请把我加入；如果必须使用单独接收规则，烦请为本人配置适用的模板。

本次申请只涉及本人日志的读取、汇总和提交，不申请企业管理员或全员日志查看权限。如您不负责钉钉模板管理，也请帮忙指明应联系哪位管理员。确认规则后，我会先完成无写入检查，再在允许的范围内启用。

谢谢老师。

## 你和老师分别怎么操作

1. 你在钉钉中切换到 iSyslab 对应组织，通过通讯录找到薛老师的已确认账号，将上面的文字发给老师；本文件只是申请稿，未代发。
2. 老师本人若不是日志管理员，请其转给负责该组织日志模板的管理员。普通成员不能靠修改本地配置获得组织端权限。
3. 管理员进入「工作台 → 日志」，定位「学生周报」「学生月报」。先核对模板使用范围是否包含你，再查看模板的接收规则与固定名单。
4. 模板设置入口在不同客户端可能叫「模板管理」「管理」「编辑模板」或「其他设置」；接收规则可能显示为「默认发给谁」等名称。这些是定位标签，未在当前 iSyslab 管理端现场确认，不能保证点击路径完全相同。找不到时使用钉钉帮助入口搜索「日志 默认接收人」「日志 模板管理员」，请客服按当前版本指引。
5. 若固定名单符合要求，优先保留现有规则；若只允许发给薛老师且共用模板不是该规则，请管理员决定是否建立本人可用的独立模板。你无需为了这一步取得整个组织的管理权。
6. 你用普通账号打开两种模板的填写页，检查可见性和接收人，不点击发送。将模板名称、完整接收人名单和老师的同意记录交给开发流程核对。
7. 程序重新读取最新模板，核对账号、接收人及字段，完成两种报告的无写入试跑。无写入检查不能证明远端一定可提交；经老师同意的首次真实提交还需取得日志ID并读回核对，老师确认收到后才算端到端验收完成。

## 仅当改用企业内部应用 API 时

目前本项目走现有 DWS 个人账号流程，不要因为模板接收人设置直接切换为企业应用。

若以后明确决定由企业内部应用接入，管理员需在钉钉开发者后台找到对应应用，为该应用申请日志读写相关接口权限；这是应用权限，不是给你个人授予企业管理员。具体权限点以实时接口文档和后台搜索结果为准。开发者还可能需要该应用的开发成员身份，授权范围应由组织管理员审核。

官方 DWS 文档提供 `dev app permission list/add` 查询、申请应用接口权限，以及 `dev app member` 管理应用开发成员。这些能力不能替代日志模板接收规则；未经决定切换路线，不执行这些操作，也不索要老师的密码或凭证。
