# 两个 ChatGPT 会话的日报监控

仅授权以下两个云端聊天，按固定 ID 跟踪，标题变化不影响选择：

| 截图中的会话 | 原生 ID |
| --- | --- |
| 标注第一章公式证明（读取接口目前返回标题“应用高等工程数学”） | `6abc7c94-c4dc-83e9-b950-256b3ce35db3` |
| 论文分析 | `6ac732ea-aedc-83e9-89c0-54f804bef8c9` |

它们不是本地 Codex 会话。Codex 应用的“18点汇总两个网页对话到日报”监控每天北京时间 18:00 读取真实聊天页面，将允许的文本通过 `python -m lablog.chatgpt_bridge` 写入 `data-chatgpt/source/<会话ID>.json`。网页及 WorkBuddy / CLI `auto` 读取同一快照，并共用各自数据目录中的持久化选择。界面新增 ChatGPT 来源及独立会话计数；不采集其他 ChatGPT 聊天。

云端同步需要 Codex 应用运行。网页本身无需保持打开；外部 WorkBuddy 发送任务不会直接登录或抓取 ChatGPT。如果超过 24 小时没有成功同步，来源会标记为过期，所选会话会阻止自动提交，避免把旧快照误当最新工作。

当前 `read_thread` 能返回真实用户消息，但助手正文是 `::chatgpt-content-reference` 引用。桥接程序跳过此类引用并记录正文不完整警告，不尝试推测助手回答。用户提问按真实时间统计，状态为计划，不能仅凭提问认定已完成研究。若未来接口提供实际助手文本，再按正文判断，并保留“未独立核验”的限定。PDF、附件、系统消息、推理、工具参数和凭证不会复制进桥接快照。

桥接快照作为本地读取源保存实际可用文本；`conversations.sqlite` 仍仅保存短摘要及消息 ID 定位，不保存完整原始对话。消息通过原生 ID 去重，重复同步不重复计数，改名和重启不丢选择；显式白名单外的会话无法导入或手动选入。

本机 `config.auto.yaml`、`config.local.yaml` 已启用同一来源目录及两个 ID。其他账号、接收人、发送时间和原有调度没有改变；本地日报配置已排除 Galgame News 与 ComfyUI 项目，ChatGPT 仍只跟踪上表两个白名单会话，Open Science 继续默认参与。

2026-10-16 验证：191 项 Python 回归通过（17.79 秒），含桥接导入、白名单、真实时间戳、用户/助手状态区分、引用过滤、过期阻断、选择持久化、移除可选配置后禁用历史会话、API 到 CLI 共享证据。4 个浏览器脚本均通过，覆盖 ChatGPT 会话/勾选/预览、来源警告、项目批选、新旧采集界面和手机布局。实机首次同步两个聊天共 8 条可用用户消息，当日 2 条，均未伪装为完成成果；本次不执行真实钉钉发送。

## 2026-10-19 更新

两个会话每日按昨天 18:00 至今天 18:00 的 24 小时窗口纳入日报，采用左闭右开边界，原始工作日期保留。仅 ChatGPT 来源启用此窗口，Codex 和 WorkBuddy 不变。两个本机配置启用 `chatgpt.daily_window.enabled`。每日 18:00 自动同步并保存单独摘要，随后已有日报流程读取快照；截止 18:00 的完整总结只能在截止点后完成。相邻日报窗口首尾相接，同一消息会进入相邻两次候选范围，不能表述为当天新完成。摘要仅基于真实可读正文，助手引用占位符继续跳过并告知缺失。周报月报保持暂停。29 项相关测试通过。
