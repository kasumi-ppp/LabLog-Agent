# 周报跨周候补工作

用户于 2026-10-17 确认周报完成部分以约 200 字作为“内容不足”的判断目标。

生成周报时先保留本周正文。低于目标时，优先补入本周尚未写进正文的完整完成事项，再选上周未进周报的事项；达到目标或候选用完即停止，不拆句、不编造内容凑字数。超过 200 字的完整事项不会被截断。

历史补充在正文标明“上周补充（原始工作日期：YYYY-MM-DD）”，不会伪装成本周新完成。只有真正采集到的 `completed` / `committed` 事项进入候选，提问、计划、进行中记录不转为成果。会话自述完成仍按未独立核验的证据处理。

## 两周窗口

- 原始工作发生的那一周及下一周可候补。
- 从下下周周一起不再选用，下一次生成时移出候选池；原始日志、证据文件、历史草稿及已提交记录不删除。
- 例如 2026-10-12 至 10-18 的工作，可以在 10-19 至 10-25 的周报内容不足时补入；10-26 起不再作为候补。
- 周五生成周报后新增的周末工作，下周仍可重新从真实来源采集进池，不会因周报在周五生成而永远遗漏。

候选按实际日期排序，优先本周，其次上周；重复正文合并并保留来源和证据关联。每次用当前配置及持续选择重新核对授权，被取消选择的来源不继续候补。前一周证据读取不会改写那一周的证据文件。

## 已使用与失败处理

日报和周报的使用记录独立：日报写过的工作仍可总结进周报。已在周报成功提交并读回确认的事项，不会再次候补；历史周报的完成字段引用也参与去重。提交结果未知或不一致的事项先保留并暂缓选用，避免重复发送。

生成草稿或提交失败都不消耗候选。用户从生成正文删掉的候补段落也不误记为已汇报；仅在实际已验证正文中仍能定位的候选才记录使用。完全改写导致无法对应时，保留候选待核对，不猜测消费。

## 配置和文件

```yaml
quality:
  weekly_carryover:
    enabled: true
    target_chars: 200
```

本机 `config.auto.yaml` 和 `config.local.yaml` 已启用；示例配置默认关闭。候选与独立周报回执保存在 `<data_dir>/weekly-pool/items.json`，日报原有 backlog 不变。CLI 和网页生成调用相同逻辑，人工保存稿及冻结提交记录继续受原保护规则约束。未更改调度时间或收件人，也未执行真实提交。
